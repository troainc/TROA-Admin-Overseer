# Bifrost product roadmap

The latest public package is **v0.8.99 — Bifrost Operations Timeline and Incident View**. It includes phases 1, 2, and supported phase 5 work described below. Remaining integrations are pending.

1. **Plugin capability and freshness:** truthful config, metrics, history, events, sample-time, stale, loading, empty, and failure states.
2. **Startup and incident diagnostics:** source-attributed lifecycle and incident timelines, without inferring missing AMP, host, Linux/Wine, storage, or world-load evidence.
3. **World visibility:** grid dossiers and Cleaner+ cleanup previews through explicit plugin APIs. Cleaner+ owns cleanup; GridVault owns backups and recovery.
4. **Safer workflows:** redacted config history and impact previews, permission previews, and separately authorized owner-plugin maintenance steps.
5. **Operational insight:** server-specific baselines, opt-in scoped alerts, incident replay, compatibility mapping, search, and accessibility.

Remaining phase features are proposals until implemented, reviewed, packaged, and published in a versioned release. Discord live presence is privileged: keep rosters behind Analytics authorization, never persist custom status text or message bodies, and label counts approximate when required intents are unavailable.
