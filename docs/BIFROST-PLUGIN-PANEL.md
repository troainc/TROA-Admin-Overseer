# Bifrost operator guide

Open the URL logged by Torch and sign in. Bootstrap the first Owner once, then create named accounts with least privilege. Secure remote access with HTTPS.

Overview shows plugin status and source-provided data. Plugin workspaces provide supported status, settings, and actions. Save/reload is delegated to owning plugins. Command console/history expose registered TROA commands with permission checks. Activity, analytics, rewards, access controls, and CPU affinity are separate pages.

For v0.8.100, Core Controller actions are state-aware: confirm Enable/Update to apply a validated selection; confirm Disable/Restore to turn it off. Cancel makes no change.

README now shows current Bifrost workspace layouts for World Overview, GridVault, Startup/World Save Health, Operations/Cleaner+, SimSpeed incidents/reports, Core Controller, and plugin health. All preview values are synthetic; they are not live-server screenshots.

Phase 1 capability cards distinguish the plugin's source sample time from Bifrost's last checked time. A check timestamp does not imply that the plugin generated a new sample. Phase 3 adds grid dossiers and an Owner/Admin-triggered Cleaner+ aggregate preview; it reveals no candidate identities or positions and does not enqueue or perform deletion. Phase 4 adds configuration history with field names only, role previews, readiness checks, and Owner-confirmed maintenance. Phase 5 adds operational baselines, replay, capability inventory, and opt-in browser-local notifications.
